Designing The Cloud


Why is the cloud such a big disruptor in the computing landscape?


On-demand: computing power using remote servers and farms

Elasticity: to scale up and down as according to demand

Multitenancy: many different clients can use the same cloud infrastructure

Cloud infrastructure can also hold virtual networks in our cloud infrastructure as well as virtual servers.


Say we have a large server farm with 100 individual computers with network infrastructure set-up to accomodate this. Switches, routers, redundancy, Next-Generation Fire Walls, ect.


We then migrate this to one very large physical server running 100 virtual servers inside. What then happens to this network and it's infrastructure?


Similarly, we virtualize the network infrastructure as well. This is referred to as:


Network Function Virtualization


So instead of the physical hardware as necessary for this previous 100 computer network, we can run the switches, routers, and all other required networking hardware virtually to perform the same functionality with these 100 virtual servers inside the machine. This can be configured and managed from the Hypervisor.


These have the same functionality as the physical device, but are running entirely within the virtualized network running on this machine. So, routing, switching, load balancing, firewalls, and other functions can be performed in this software only environment.


This, naturally, makes deploying modifications to the network as easy as a push of a button. Additionally, this allows for complex interactions between containers, virtual machines, and access for different clients on on the network.


Virtual Private Cloud (VPC)


This is one very common form of cloud computing seen in commercial and enterprise configurations. It is a pool of resources created in a public cloud, allowing for easy storage and retrieval of files or other data as required.
