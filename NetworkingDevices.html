Networking Devices


If you were to walk through a data center, you would see a lot of server racks together with a lot of different equipment installed in each one of them.

All of these devices work together to take data from one end of the network and move it to another part of the network.

Each of these devices is installed for a different reason, and its helpful if we understand why we installed that particular piece of equipment to begin with.

Over time we may be installing more of this existing infrastructure into our racks or we may be installing new technology.


So in this segment, we will be looking at different types of devices and how we may use them in our data center.


The Router


Allows us to take data from one IP subnet and take it to a different IP subnet. These subnets may be next to each other, or on different parts of the world.

The router is an OSI layer 3 "Network" layer device.

The OSI layer 3 deals with IP addresses, and the router uses IP addresses to determine the next hop for this information.

You may also see this routing functionality inside of an existing Switch. These are often referred to as "Layer 3 Switches".


These routers often connect many different types of networks, such as LAN (Local Area Network), WAN (Wide Area Network), copper, or fiber based connections.

So we may have routers with many different connectors on them, connecting many diverse networks to all of those different interfaces.


The Switch


Switches operate at the MAC address layer (layer 2) to be able to forward traffic.


These operate mostly in hardware. The hardware inside of these devices is referred to as an ASIC (Application-Specific Integrated Circuit).


Switches contain many ports and features. For example, many of these switches may provice power over the ethernet connection (PoE). Additionally, as mentioned before, you may also have multilayered switches which include layer 3 functionality built into the device.


Firewall


Security is also important for any network.


A traditional firewall allows you to filter traffic based on a TCP or UDP port number, however more modern firewalls are using NGFW (Next Generation FireWall) which is able to identify applications traversing the network and allow you to manage if that application should be allowed or not allowed on the network.


Most firewalls also have additional functionalities, for example it is common to find firewalls that allow you to encrypt traffic traversing the network through a VPN (Virtual Private Network). It's very common to have one firewall at one remote site and another at another remote site, which then allows you to create an encrypted tunnel between those firewalls using the VPN functionality.



Most firewalls can also be layer 3 devices, which means they can act as a router. Thats because they sit on the ingress/egress of the network where all the traffic on the inside of your network is going to the outside/internet connection and your internet traffic is coming inbound to your local network. You rely on the firewall to manage the connection between the inside and outside of your network.


To be able to perform this functionality, many firewalls often provide network address translation (NAT), and because they are a router, it is very common for them to have routing protocols supported inside.


IDS and IPS


Many data centers may have standalone IDS (Intrusion Detection System) or IPS (Intrusion Prevention System) devices, although much of this functionality is already integrated into the more modern NGFW.


Both of these work in similar ways. They're looking for attacks that are inbound to your network and are able to identify, alert, and in many cases prevent that attack from gaining access to your network.


These are commonly known attack types. These might be exploits against operating systems or the applications you are using, and they might take advantage of known vulnerabilities with these applications or systems by taking advantage of buffer overflows, cross-site scripting, or other known vulnerabilities.


If you're using an IDS, it is able to alarm or alert if it ever sees any of these inbound attacks. If you're using an IPS, it's able to go a step further and block that attack before it gets inside your network.


Since an IDS is not able to prevent that inbound attack, it is more common to see an IPS or a mixture of both on enterprise networks.


Load Balancer


You may have wondered how a site with millions of users is able to remain up and running without any kind of down-time.


In most cases, it is because that site is using a load balancer to be able to distribute that load across many physical servers. As the end user, you mau have no idea that this load balancing is even taking place. Think layering in modern World of Warcraft.


But if you were to look at the data center for this organization, you might find a large number of web servers or database servers and farms that can be used in conjunction with this load balancer to maintain uptime and availability.


These load balancers are also very good at identifying and outages to these servers so if one of the servers goes down, then the load balancer can recognise the issue, take that server out of the rotation and continue to provide access to these services with the remaining devices that are connected.


So a simple distribution for a load balancer would look like:


Servers A-D --> Load Balancer --> The Internet

So the end user may think that they are accessing the server directly, but they are actually accessing the load balancer that is distributing traffic between Servers A to D. Load balancers can also optimize the communication, for example performing TCP offloading so that the communication between all servers and the balancer are happening as quickly as possible.


These load balancers can also act as an SSL offload, which means they can also provide encryption and decryption capabilities instead of having the servers themselves handle that process.


Data may also be cached on the load balancer, so requests made to the load balancer could be answered immediately instead of going all the way to the server to provide that data.


Load balancers are also very good at prioritizing different types of traffic over others. There might be certain web pages that have higher amounts of access than others, and you can commonly perform that prioritization using QoS (Quality of Service).


Load balancers are also capable of performing application-centric balancing, where certain services or pages are located on different servers and all of the requests to those pages would go exclusively to the individual servers.


Proxies


Many organizations have security concerns about individual users having direct communication with the server or service thats on the internet.


One of the ways that the organization can manage this is putting a device in the middle of this conversation called a Proxy. This proxy is responsible for taking the user's request, performing that request on their behalf, receiving the answer to that request, verifying that the answer doesn't contain some type of malicious software or malicious code, and then providing that answer to the end user.


This is the purpose of a proxy. To sit in the middle of the communication and to make that communication on the users behalf. Since the proxy is sitting in the middle of the conversation, its a perfect place to do caching. The user can make a request to a web server and if that request has already been cached by the proxy server the answer can go right back to the user without having to access the internet.


We might also provide access control from the proxy server so we can request a username and password from the user in order to gain access to the internet. From that point, we might want to filter urls and perform some type of content scanning to ensure the user is not getting any type of malicious software.


Some proxies require you to configure the operating system or the applications that you're using to identify the proxy and be able to use that to be able to send and receive communication. Not all proxies work in that explicit manner; there are also transparent proxies that will work invisibly without making any changes to the operating system or the applications in use.


NAS vs. SAN


Its very common to store documents and other files on centralized storage facilities inside of our data centers. One type of storage is called a NAS (Network Attached Storage). We often refer to this NAS as providing file level access. That means that if we want to gain access to a file, we want to pull the entire file across the network into our system, and when were wiping or changing information in that file we will need to write the entire file back to the NAS.


A more efficient way of communication might be through the use of a SAN (Storage Area Network). This is very similar to reading and writing information from a local storage drive. Instead of copying the entire file to be able to change a bit of it, we have block level access which means we can change just the blocks that have been modified. When you have very large files, this can be a very efficient way to modify just a little bit of information within that ver large document.


Whether you're using a NAS or a SAN, you're probably transferring a lot of files to these systems. For this reason, we want to be using the most efficient method of communication. Its very common, for example, to put the NAS or SAN on it's own isolated network and its commonly a network that has very high bandwidths.


Access Point


If you're in your office and you look at the ceiling you might see an AP (Access Point). This device allows us to communicate wirelessly from our device to the rest of the network. This is not a wireless router that is commonly seen in households, which is a router, wireless access point, and a switch all in the same device. When you're at enterprise environments, you're usually using a device that is purpose built for a single function.


Using an Acsess Point means we are using this for wireless communication and wireless communication only.


On the other side of this Access Point is usually an ethernet connection. This is bridging connection between the wireless network and the wired ethernet network. This is why we refer to Access Points as an OSI Layer 2 device.


In most businesses of any size we likely have more than one Access Point. This is because we likely have a large building or series of buildings and you need to be sure that every location is able to access that wireless network wherever they happen to be inside that/those buildings. This means we have to manage all of these wireless access points wherever they might be in our local network or our remote site network. Additionally, we will have to manage security settings, access policies, and other configuration perameters within that access point.


We also have users that may be very mobile and may be moving from one part of the building or between sites. We need to make sure they can seamlessly roam from one access point to the other so they are always connected to the network.


Wireless LAN Controllers


Instead of connecting to each individual access point to make these configuration changes or manage this process, we can have a centralized management tool that allows us to manage all of our access points from one central place. This is a Wireless LAN Controller. This gives us that 'single pane of glass' so that we can manage the entire infastructure while were sitting in one location.


From this single device, we can deploy new access points with a single configuration, we might want to set up performance or security monitoring and be alerted if we happen to see anything across any of our access points. We can also make any changes that we need to make and deploy those automatically to all of our access points with one click of the mouse. This also allows us to create reports on how much our access points are being used and be able to understand if we need to update or change any of our access point locations.


These are often proprietary systems, so if we have an access point from one particular manufacturer we also have a Wireless LAN Controller that is also from that manufacturer.
