Networking Functions


If you were to somehow get inside of the networking cable and see what was going back and forth over that connection you would see there was a lot of different activity going on between many different systems.


All of these are designed to focus on specific functions. For example, we may need to get a piece of data from our network to a network that is on the other side of the world. Or we might need to access a system that is already located somewhere else and provide technical support and be able to share a screen.

There is also a need to have traffic management on our network so that certain applications have a higher priority than other applications.

And lastly, we need to ensure that all of our systems are up and available and it may take specialized protocols to make sure that this occurs at every step along the way.


Content Delivery Network (CDN)


This is designed to provide a way to get data from one central point to an end user very efficiently. These are often set up in geographical areas, allowing for fast content delivery to users from their given locations such as North America, South America, Europe, Australia, and so on.


You are able to cache information from each of these points. It takes time to get data from one end of the world to another, so if you can have all the North American traffic go through the North America CDN, this is much faster than having them all go out to a centralized server that may be located in Europe.


CDNs are invisible to the end user. For example, if you were to watch a particular video on Youtube's North American CDN vs their European CDN, these sites would appear functionally identical.


Virtual Private Network (VPN)


This allows the user to connect to a remote network while sending all of this data encrypted accross the network. This is a very secure way to transfer data even accross networks that would be inherently insecure, such as the public internet.


People often use a device called a Concentrator or a head-end device to be the central connection point for all the users that are accessing this VPN. This is often a purpose built appliance that is designed to do high speed encryption and decryption of network data in real time so that you can have many people send secure data accross the network, decrypt it at the end-point, send it to the inside of the network, and then reverse that process back to the user.


This can be a standalone device, but very commonly it is integrated within a NGFW (Next Generation FireWall). Because of the encryption and decryption process required to perform this VPN concentration, we usually will use a purpose built appliance or piece of hardware to be able to do this. This device should provide very high throughput and support hundreds or even thousands of users simultaneously.


But if you have a smaller network you may not need a purpose built appliance and there are many VPN concentrators that exist as software on an existing operating system.


You may have to install a specialized piece of software to be able to use a manufacturers VPN, although there is VPN software that does ship with Windows, MacOS, and Linux operating systems so that you can connect to many kinds of VPNs using that generic software.


Quality of Service (QoS)


Not all applications are designed to run simultaneously on a network and certainly some applications may have a higher priority to your organization than other applications. For example, there might be a real time audio or video stream that has a higher priority than a file transfer.


Because of these requirements, its very common for network administrators to provide some type of prioritization to these applications. This is often done through a Quality of Service (QoS) configuration. You might also refer to this as Traffic Shaping or Packet Shaping.


This allows the administrator to control what type of applications can flow through their network. Usually based on bandwidth usage or particular data rates. This might allow your real time applications to have full control or access to the network and put a lower priority on other applications that may simply be transferring files.


To control this Quality of Service you may need configuration changes inside of a Firewall, a Router, or a Switch. These devices might have a prebuilt list of applications and might also allow you to add your own applications to the list. And at this point you can decide what priority the applications might have relative to everything else that is running on the network.


Time to Live (TTL)


One of the challenges we often run into with technology is that it's very good at performing a task. Often, it can perform these tasks over and over and over again without any type of human intervention. Unfortunately this can also put a device into a state where it's performing a task over and over and over again and never finds a way to complete or end that particular task.


For that reason, we've often built in different functions with our protocols so that we can recognize when a task may be going on too long and simply remove that task from the network.


One common way to provide this identification is through the use of a Time to Live (TTL). A TTL is effectively some type of timer. This timer may be based on the time of day, or based on the number of iterations that a particular task completes, or other parameters. Once that timer hits zero, we can then have that task stop or have that task drop from the network.


There are many different cases for a TTL. One is a packet that is constantly looping between different routers; we may want to have that packet automatically drop if that loop occurs a certain number of times. Another good example of a TTL is to clear a cache. We may access a website, have that website stored in a cache, and then that cache is only available is only available for a certain amount of time. Once that time hits zero, the cache is cleared and the next time that website is accessed you would have to all the way out to the site to be able to bring that information back. At that point, that information is cached and another timer starts.


TTL In Routing Loops


One other example of using a TTL to stop traffic that is looping around your network is a Routing Loop.


An example of a routing loop is that Router A (10.1.10.1) thinks the next hop is to Router B but Router B (10.2.10.2) thinks the next hop is to Router A. Thus having the packets travel in a loop.


If you were to perform a trace route, you would see this loop in the trace route itself. Where the route goes:

10.1.10.1 --> 10.2.10.2 --> 10.1.10.1 --> 10.2.10.2

And so on, until TTL reaches 0.


This can happen occassionally. It is easy to misconfigure, as your enterprise may have many different routers and those routers may have many different routes.


For routing loops, we use a TTL field inside of the IP packet itself. This allows us to identify and stop a loop automatically if it occurs.


TTL In Internet Protocol (IP)


We build functions within IP to look for the above routing loop to occur and stop it if it is occuring over and over.


In IP, the TTL is referring to the number of hops that a packet will go through a router. Each time a router processes the packet, it decreases the TTL by 1. When that value gets down to 0, it discards the packet which ends the loop.


The default TTL for a packet in MacOS and Linux is 64 hops.

The default TTL for a packet in Windows is 128 hops.

Transport Layer Security


In most cases, the total number of hops that it takes for our packet to leave our network out to the greater internet is somewhere between 12-16 hops. However, there may sometimes be more and sometimes less depending on network configuration.


This is a relatively small number when considering the default number of hops allowed by Time to live on MacOS, Linux, and Windows.


This gives us plenty of room to get data from one side of the internet to the other and not have that information accidentally dropped by a router.


TTL In DNS (Domain Name System)


Depending on the protocol you're using, the TTL may have a different definition.


With routers, TTL is associated with the number of hops. However, with DNS (Domain Name System) the TTL is associated with the total number of seconds.


In the scenario where we are performing a DNS lookup, by using nslookup or dig, you can look up a web domain and the dns server will return some type of IP address associated with the domain name.


Inside of that DNS resolution is information about TTL. This tells us how long we should cache this local entry on our system. So, we want to cache it for a certain number of seconds. How long? It'll be the TTL length.


When using dig on www.professormesser.com, it'll return some variation of this output:


user@hostname.com ~ % dig www.professormesser.com


; <<>> DiG 9.10.6 <<>> www.professormesser.com

;; global options: +cmd

;; Got answer:

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 63255

;; flags: qr rd ra; QUERY: 1, ANSWER: 3, AUTHORITY: 0, ADDITIONAL: 1


;; OPT PSEUDOSECTION:

; EDNS: version: 0, flags;; udp: 512

;; QUESTION SECTION:

;www.professormesser.com. IN A


;; ANSWER SECTION:

www.professormesser.com. 300 IN A 172.67.31.114

www.professormesser.com. 300 IN A 104.22.72.108

www.professormesser.com. 300 IN A 104.22.73.108


;; Query time: 51 msec

;; SERVER: 9.9.9.9#53(9.9.9.9)

;; WHEN: Wed Mar 06 13:52:34 EST 2024

;; MSG SIZE rcvd: 100


As you can see in the answer section, it says that the server www.professormesser.com has a TTL of 300, it is an internet address (IN A), and then we see the 3 different IP addresses associated with the web server.


So we can see that the TTL for this web server is 5 minutes. Once this 5 minutes has passed, the local cache will remove that particular resolution. And if you wanted to see the IP address for that same server again, you'd need to perform another DNS query to update the cache for another 5 minutes.


This allows the administrator to change the IP address in their DNS configuration and they will know that most people will have an updated version of that IP address within 5 minutes.
